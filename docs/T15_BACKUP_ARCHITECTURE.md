# HomeTechVN — T15 BACKUP ARCHITECTURE

Status: T15 candidate.

## 1. Objective

T15 creates an independently recoverable backup set for HomeTechVN.

A backup is not accepted merely because a dump command succeeded. The stage
requires:

1. real remote logical backup;
2. payload checksums;
3. source archive without secrets;
4. Storage completeness check;
5. actual restore drill against a disposable local database;
6. retention and schedule support.

## 2. Current project state at T15

Remote preflight on 31/08/2026:

```text
PostgreSQL        17.6
Database size     approximately 18 MB
Storage buckets   0
Storage objects   0
```

Because there are currently zero Storage objects, T15 can reach FULL backup
status without S3 credentials. If Storage objects appear later, the backup
script refuses FULL status until S3 backup is configured and verified.

## 3. Backup set layout

Each production run creates:

```text
HomeTechVN_YYYYMMDD_HHMMSS/
├── manifest.json
├── checksums.sha256
├── source.zip
├── database/
│   ├── roles.sql
│   ├── schema.sql
│   ├── data.sql
│   ├── history_schema.sql
│   ├── history_data.sql
│   └── storage_metadata.sql
└── storage/
    └── <bucket>/...
```

`LATEST.txt` in the backup root points to the latest completed backup directory.

## 4. Database logical backup

T15 follows the Supabase logical-backup pattern:

```text
roles.sql
schema.sql
data.sql
```

Additional HomeTechVN files:

```text
history_schema.sql
history_data.sql
```

preserve the Supabase migration ledger.

`storage_metadata.sql` is an explicit audit/export of Storage metadata.

It is not a substitute for Storage object bytes.

## 5. Storage backup

Supabase database backup contains Storage metadata, not the actual object bytes.

T15 therefore has two states:

### Storage empty

```text
metadataObjectCount = 0
storage.status = NOT_REQUIRED_EMPTY
```

This is FULL.

### Storage contains objects

FULL status requires:

```text
Supabase S3 credentials
rclone
remote object count == local object count
remote byte count   == local byte count
```

If objects are present but S3 backup is not configured:

```text
status = FAILED
storage.status = OBJECTS_PRESENT_S3_BACKUP_NOT_CONFIGURED
```

The script deliberately refuses to call that backup complete.

## 6. Source/config backup

`source.zip` captures the HomeTechVN source tree while excluding:

- `.git`
- `node_modules`
- `dist`
- Supabase temp data
- Worker generated data
- local snapshots
- backup output
- `.env`
- `.env.local`
- any `.env.*` except `.env.example`
- `worker/.dev.vars`
- log files

No database password, S3 secret, provider token or service-role secret is
intentionally included.

## 7. Secret storage

T15 does not keep backup credentials in Git/project files.

Local Windows paths:

```text
%LOCALAPPDATA%\HomeTechVN\Backup\config.json
%LOCALAPPDATA%\HomeTechVN\Backup\secrets.json
```

`secrets.json` stores only DPAPI-encrypted ciphertext generated by
`ConvertFrom-SecureString`.

The database password is entered through a SecureString prompt and URL-encoded
before the final database URL is encrypted.

The Windows user running the scheduled backup must be the same user that
created the DPAPI ciphertext.

## 8. Integrity

Each backup contains `checksums.sha256`.

T15 verifier recomputes every recorded SHA-256 before accepting the production
backup.

The manifest explicitly records:

```text
format = hometechvn-backup-v1
status = FULL
secretsIncluded = false
storage status/count/bytes
database file paths
source archive path
```

## 9. Restore drill

T15 creates a disposable local Postgres database from the fully migrated local
Supabase baseline.

The drill then:

1. clones the clean baseline;
2. inserts a restore marker into the source only after cloning;
3. creates a custom pg_dump of application-owned `public` + `private` data;
4. truncates application-owned data in the scratch database;
5. restores the dump with `pg_restore`;
6. verifies the marker;
7. compares row-count signatures for critical tables;
8. checks archive structure with `pg_restore --list`;
9. drops the scratch database.

This is a real data restore, not a syntax-only test.

The drill is intentionally performed on a disposable local target and never on
the production database.

## 10. Retention

Default:

```text
30 days
```

Retention only deletes old directories whose `manifest.json` declares:

```text
format = hometechvn-backup-v1
status = FULL
```

Failed/partial/unreadable backups are retained for investigation.

## 11. Scheduling

`scripts/t15-install-schedule.ps1` creates a daily Windows Scheduled Task.

Default suggested time:

```text
02:15
```

The task uses Interactive logon to avoid storing the Windows account password in
the Task Scheduler definition.

## 12. Database migration policy

T15 adds zero database migrations.

```text
T1 → T13 = 33 locked migrations
T14         0 DB migrations
T15         0 DB migrations
```

Backup infrastructure is operational tooling, not a schema change.
