# HomeTechVN — T14 PWA ARCHITECTURE

Status: T14 candidate.

## Goal

Install HomeTechVN like an application on:

- Windows with Microsoft Edge / Google Chrome
- Android with a PWA-capable browser
- ChromeOS / Chromebook

The same HTTPS Cloudflare Pages deployment remains the application origin.

## Service Worker strategy

T14 uses Workbox through `vite-plugin-pwa` with:

```text
registerType: prompt
skipWaiting: false
cleanupOutdatedCaches: true
runtimeCaching: []
Background Sync: NONE
```

Precached resources are limited to the application shell/static resources:

```text
JS
CSS
HTML
PNG
SVG
ICO
webmanifest
```

T14 does not configure a runtime cache for:

- Supabase REST/RPC/Auth
- notification providers
- Telegram
- email
- Zalo
- Cloudflare Worker APIs

## Offline policy

HomeTechVN v1 does **not** support offline transaction writes.

When `navigator.onLine` becomes false, `PwaShell` places a modal lock over the
whole application.

The offline lock explicitly blocks operational use until Internet returns.

No Background Sync queue exists. Therefore failed writes are not silently
replayed later.

The app shell can still open from the PWA cache and explain the offline state.

## Update policy

Updates use a prompt instead of automatic reload.

Reason:

A forced reload while a user is entering a sales order, repair note, warranty,
service or configuration could discard unsaved local form state.

When a new Service Worker is ready, HomeTechVN shows:

```text
Có phiên bản HomeTechVN mới
[Cập nhật] [Để sau]
```

Selecting `Cập nhật` activates the new Service Worker and reloads.

The installed app also asks the Service Worker registration to check for
updates approximately once per hour while online.

## Public Warranty

`/w/<token>` continues to use the T12 privacy rules.

The route may load the cached application shell while offline, but the global
offline lock prevents presenting stale warranty data as current data.

## Cloudflare Pages headers

`/sw.js`:

```text
Cache-Control: no-cache, no-store, must-revalidate
Service-Worker-Allowed: /
```

`/manifest.webmanifest`:

```text
Cache-Control: no-cache
```

T12 `/w/*` `noindex/no-referrer/no-store` rules remain unchanged.

## Database

T14 introduces no database schema/function change.

Migration baseline remains:

```text
T1 → T13 = 33 migrations
T14 database migrations = 0
```

Creating a no-op database migration merely to increment the stage number is
explicitly prohibited.
