# HomeTechVN — T17 v1.9 FIX NOTE

Date: 01/09/2026

## Windows v1.8 finding

The v1.8 verifier successfully reached `supabase start`, replayed all 36
migrations, and then failed only because these unrelated local-development
services were unhealthy:

```text
supabase_storage_HOMETECHVN
supabase_studio_HOMETECHVN
```

The log also shows the Windows Analytics warning.

T17 does not exercise Storage, Studio, Analytics, Realtime, Edge Functions,
Mailpit, postgres-meta, or Supavisor. Making those services part of the T17
acceptance gate created an unnecessary platform/CLI failure surface.

## v1.9 minimal integration stack

T17 now starts only the services needed for the integration contract:

```text
Postgres
GoTrue / Auth
Kong API gateway
PostgREST
```

Using the official `supabase start -x` exclusion mechanism, T17 excludes:

```text
realtime,storage-api,imgproxy,mailpit,postgres-meta,studio,edge-runtime,logflare,vector,supavisor
```

T17 does **not** use `--ignore-health-check`: health failures of the services
that T17 actually depends on still fail the verifier.

## Empty first-run / clean-data policy

T17 fixtures are temporary verification data only.

The acceptance flow is now:

```text
baseline
→ create local demo users/data
→ run integration/Auth/JWT/RLS/build checks
→ restore any pre-existing app/.env.local
→ supabase db reset --local
→ assert all Auth/business transactional tables are empty
→ PASS
```

The normal `supabase/seed.sql` contains only system foundation data such as:

```text
roles
permissions
role-permission mappings
non-secret settings
```

It does not seed real users, customers, products, orders, repairs, warranties,
or other business records.

Therefore a completed HomeTechVN installation starts operationally empty and
real data is created only when the user begins using the system.

## Token policy

No secret/service-role token is required for T17. Do not paste secret keys into
chat or commit them to source. The local publishable key is generated by the
local Supabase stack and resolved automatically.
