# HomeTechVN — T17 v1.6 FIX NOTE

Date: 01/09/2026

## Windows v1.5 finding

The global PowerShell checker recursively scanned every `.ps1` below the project root. After `npm ci`, that includes npm-owned shims in `node_modules/.bin`, whose encoding is controlled by npm and is not part of HomeTechVN source.

It also scanned `scripts/OK_check-prerequisites.ps1`, a legacy leftover on the Windows working directory that is not present in the T17 v1.5 source archive.

These were false ownership assumptions, not T17 business/database failures.

## v1.6 correction

T17 now ships `scripts/t17-powershell-managed.json`, containing the exact 30 PowerShell files owned by the current checkpoint.

The static checker validates only those manifest-listed files for:

- UTF-8 BOM;
- ASCII-only parser-critical source;
- no literal TAB;
- no line-leading pipeline operator;
- quote/bracket/here-string lexical balance.

Other `.ps1` files are informationally counted but ignored, including:

- `node_modules/.bin/*.ps1` generated by npm;
- legacy/untracked files left by older overlays;
- future vendor/generated PowerShell not explicitly added to the checkpoint manifest.

A newly added project PowerShell file must first be added to the managed manifest before it can be accepted.

## Database impact

None. Migration chain remains 36/36; T17 DB migration = 0.
